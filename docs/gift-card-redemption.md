# Gift-card redemption and refunds

Gift-card value is prepaid tender, separate from promotional reward credit. It can cover the full service price on marketplace, provider and quote checkout. The marketplace/provider cart uses gift-card value; the quote flow retains its existing capped promotional rewards. Unused gift value remains available. A nonzero USD card remainder must meet Stripe's minimum, so a remainder below $0.50 uses slightly less gift value to leave a $0.50 card payment, preserving the extra gift balance.

`rewardWallets/{uid}.balance` remains the total. `giftBalance` identifies its prepaid portion. Legacy wallets derive their remaining gift portion from existing ledger entries without changing the total; the next ledger mutation persists the split. Debits and restorations are transactionally recorded once under deterministic checkout/refund keys. Unpaid expired or terminally failed sessions return the exact held gift/reward amounts. Failed restoration throws so the webhook is retried.

Server-only checkout terms/orders and debit ledger entries prove funding. Full-credit orders accept Stripe's paid/no_payment_required completion without inventing a PaymentIntent. Each crew still has its own code and the same 85% allocation of its full service subtotal. Credit-funded transfers use the existing platform Stripe balance, rather than trying to transfer more than a smaller new card charge. Insufficient/pending balance is held for existing payout follow-up; no other account or automatic bank payout setting is changed.

The owner approved refunding original tenders: gift value returns to gift balance, promotional rewards return as rewards, and card amounts return to the card. The $5 review incentive is split proportionally between the job's gift and card tenders, with any star rating qualifying. Gift-only review refunds credit $5 once; mixed refunds wait for successful card refund processing before restoring the gift portion. Provider allocation is unchanged. Tips still require review and retain their existing 90% provider/10% processing allocation.

Admin job cancellation now calls an authenticated server refund endpoint with explicit confirmation. It refunds the full original tender amounts before release only. It does not set cancellation fees or reverse provider transfers. Released jobs, disputes and unexplained prior refunds require manual reconciliation. Pending/failed cancellation refunds are shown in Mover payment follow-up. Refunded/disputed original gift purchases block redemption or spending for review rather than silently deleting customer balances.
